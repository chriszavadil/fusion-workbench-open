# Implementation admission: first evidence-linked visual workbench

## Research before implementation

The purpose is to turn selected existing results into inspectable geometry and a traceable test interface, not invent another fusion solver. Official Blender glTF/USD documentation supports object custom properties and portable mesh exchange. Epic documents the USD Stage Actor and explicitly restricts Python to editor use. Paramak already creates parameterized fusion CAD and remains a candidate for later engineering geometry; this display-only prototype does not replace or reproduce it. Three.js supplies the browser renderer. Existing upstream APIs are reused.

## Boundaries and acceptance

This milestone uses two authenticated MFILE outputs. Extract numerical allowlisted fields, independently verify their pulse-energy and gross/load balance, and generate two separate visualization envelopes. A cutaway is a display state, not a new reactor configuration. Never present component scalars as resolved fields.

One live deterministic reproduction is justified only as integration verification of the approved job bridge. No physics optimization campaign, parameter sweep or new scientific claim is admitted. Stop that test at success, a specific implementation error or the ten-minute timeout, retaining its private log and safe status.

Verify that the browser can change configurations, inspect components, replay real stored profiles, show honest evidence gaps and run an allowlisted local test. Generate and inspect Blender geometry and attempt an Unreal scene import with metre/centimetre validation. Missing functionality remains marked as pending rather than implied by controls.

Release originals under MIT and project-only attribution. Do not publish private history, hostnames, personal paths, credentials, emails, account URLs or raw logs. Export only explicit reviewed files, preserving third-party notices. No public deployment under a personal account is authorized by the anonymous-branding choice.
