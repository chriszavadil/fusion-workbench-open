# Public release boundary

Publication under the existing GitHub username is authorized. The original private research repository and its history stay private; the public repository starts with a clean, reviewed source snapshot.

Only explicitly selected source, permission-cleared research records, generated display assets and the tested Windows runtime are released. Private correspondence, home paths, machine identifiers, execution adapters, raw logs, debug symbols, authentication material and compiler installations are excluded. GitHub account association is intentional; it does not authorize releasing other personal information.

Authentication is handled locally for GitHub operations. Credentials must never be printed, written into release files, copied into issue bodies or embedded in Git history. Published commit attribution uses the project contributor identity rather than a private email address.

Automated scans supplement review; they do not guarantee the absence of every possible disclosure. The release records the review scope and the independent limitations of numerical, experimental and geometry evidence.

The Windows executable is an unsigned research preview, not an operating reactor, safety tool or validated digital twin. Fresh calculations require an optional, explicitly configured local worker. No public remote execution service or automatic X post is created.
