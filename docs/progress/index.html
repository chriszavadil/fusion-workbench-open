What is the timeline?

Before the next run: inputs, prior work, a finite run budget and a test that could reject the idea. Next: a matched plasma/current calculation. After it passes: the heating/current-drive test. In parallel: reusable benchmark and engineering-data review. Later: same-design integration and authorized physical tests.

These are checkpoints, not a calendar promise. A credible completion estimate needs an owner, complete inputs and an execution plan. Missing those is shown as “not scheduled,” not hidden.

CHECK EXISTING WORK BEFORE SPENDING COMPUTE

Reuse it. Credit it. Do not call it a new discovery.

This uses the existing prior-work register, not a new competing list. Every goal links to methods it should reuse.

Do not repeat a completed test with the same inputs and question.

Reopening needs changed evidence, a real defect, or a named independent-verification gap. Useful reproduction is allowed—but labeled reproduction, not breakthrough.

What automatic checks enforce—and what they cannot

The builder rejects unclassified milestones, missing sources, unknown prior-work references, goals without pass/stop criteria and circular dependencies. Task-review checks flag unchanged repeats without a specific verification need.

These checks do not prove novelty. Someone must still read the relevant work, compare inputs and decisions, and document why another calculation is worthwhile. The code does not search all science or execute submitted code.
