# Data and geometry scope

The public numerical dataset is an explicit projection of selected project-generated PROCESS outputs. Each configuration carries its source artifact SHA-256, upstream solver reference, dimensions, electrical profiles, assumptions and limitations. Source paths, account names and raw textual headers are not copied into this projection. Public verification can reproduce the displayed arithmetic without obtaining the private originals; exact re-execution additionally requires the pinned upstream inputs and runtime adapters, which have a separate disclosure review.

Seven-point pulse profiles are linearly interpolated for display because the recorded energy account uses those segments. Interpolation adds no physics. The graph labels its generating interval separately from dwell and additional assumed availability.

The plasma outline is an analytic visualization derived from radius, elongation and triangularity. It is not the solver's reconstructed equilibrium. First-wall, blanket, shield and vessel surfaces interpolate native dimensional constraints; they are not heterogeneous CAD or volume-certified solids. TF-coil count is native; paths and section shapes are schematic. Central-solenoid bore, width and height are linked, but winding and qualified material details are absent.

Heat, stress and neutron overlays are not synthesized from component-level scalar values. A future resolved field must state mesh coordinates, units, normalization, solver provenance and compatible configuration ID before it can be displayed as a field.

Inventory includes tracked project files categorized by topic, not personal emails or every file on the workstation. Older reference-machine scenes, all past raw trajectories, incoming experimental data, manufactured piping geometry, neutron transport and a complete radiation/thermal stress solution are not included in this first slice.
